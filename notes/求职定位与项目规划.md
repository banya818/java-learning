## 六、项目设计

> **2026-11-11 修订**：原方案是「自研知识库 + AI 问答」，已废弃。理由是零基础 + 130h + 2/28 截止，没有教程兜底的自研项目大概率做不完，而跑不起来的项目在简历上等于零。现方案改为**用苍穹外卖教程做骨架，再叠加改造点**。

### 决定：跟教程做骨架 + 三个改造点

| 部分 | 内容 | 时间 |
| --- | --- | --- |
| **骨架**（跟黑马苍穹外卖） | 员工/用户登录、分类、菜品、套餐、订单、支付回调、微信登录 | **90h** |
| **改造一（必做）** | Spring AI + RAG：商品/订单知识库问答 | **25h** |
| **改造二（必做）** | Redis 缓存优化：商品详情缓存 + 穿透/击穿/雪崩 | **15h** |
| 改造三（可选） | 分布式锁 + 库存扣减（Redisson） | 时间够再补 15h |

合计 130h，和 2.13–2.27 的窗口对得上。

### 三个改造点的面试价值

| 改造点 | 能讲多久 | 三层追问 |
| --- | --- | --- |
| **RAG 知识库**（必做） | 15 分钟 | 切片多大、为什么 / 召回不准怎么办 / 怎么防模型胡说 |
| **Redis 缓存**（必做） | 10 分钟 | 缓存什么、为什么是这些 / 穿透击穿雪崩怎么防 / 和数据库一致性怎么保 |
| 分布式锁（可选） | 10 分钟 | 为什么用 Redis 不用数据库锁 / 锁超时怎么办 / 防止误删别人的锁 |

**为什么是 RAG 而不是「接大模型做智能客服」**：智能客服只是调 API，面试问两句就到底。RAG 才命中 JD 原文——抓到的 JD 里写着 `RAG、Agent、知识库、Prompt 工程`、`向量库 Milvus / PGVector`、`MCP`、`Function Calling`。智能客服不在这张清单上。

### 命名：别叫「外卖系统」

简历上写「**XX 餐饮 SaaS 平台**」或「**本地生活服务平台**」。

不是骗人：架构参考了开源教程，业务梳理和三个改造点是自己做的。面试时如实说「参考了开源项目的分层架构，业务和 AI 模块是自己设计实现的」——这样既不减分，也守住了诚实。

### 加餐项目：短链服务（可选，约 2 周）

只在 3–4 月有余力时做。骨架项目偏业务，证明不了技术深度；短链代码量 800 行以内，但能讲透四件事：

1. 发号器：Redis 自增 vs 雪花算法，各自的问题
2. Base62 编码：为什么不用 MD5 截断
3. 缓存：热点 key 怎么设计，缓存穿透怎么防（布隆过滤器）
4. 跳转：301 还是 302，为什么

**它的作用不是替代主项目，是在面试里证明「我不只是会 CRUD」。**

### 明确不做

- **只照抄不改**——2027 年外卖简历人手一份，不改等于自曝短板
- 微服务（时间不够，碰了等于什么都没做）
- 秒杀（需要压测、限流、分布式锁，讲不明白）

## 七、简历项目部分的写法

### 结构：动作 + 技术 + 结果，一行一件事

```
餐饮 SaaS 平台 | Java 后端 | 个人项目 | 2027.02–2027.03
技术栈：SpringBoot 3 + MyBatis-Plus + MySQL 8 + Redis + Spring AI
· 基于 JWT + 拦截器实现员工/用户双端鉴权，按角色隔离订单与菜品管理权限
· 商品详情接入 Redis 缓存，实测命中率 87%；空值缓存防穿透、互斥锁防击穿
· 基于 Spring AI + 向量库实现商品/订单知识问答，文档切 512 token，Top-3 召回
· Redisson 分布式锁控制库存扣减，100 并发压测无超卖
```

### 五条硬规则

1. **不写功能清单**。「实现了用户的增删改查」等于没写，谁都会。
2. **数字必须自己测过**。面试官一定问「怎么测的」，编的撑不过两个追问。
3. **写上去的每个技术点都要能被追问三层**。写了 Redis 就要能答缓存穿透、雪崩、一致性。
4. **技术栈不堆砌**。写了 SpringCloud 就要能讲注册中心原理，讲不出就是减分。
5. **项目名别叫「XX管理系统」**。叫「知识库共享平台」「短链服务」这种，一眼看出是做什么的。

### 简历整体排序（重要）

```
1. 项目经历      ← 二本学历下，这是唯一能翻盘的部分
2. 专业技能      ← 分「熟练/熟悉/了解」三档，别全写熟练
3. 教育背景      ← 二本放后面，不占首屏
4. 其他          ← 蓝桥杯、GitHub 链接（绿墙）、博客
```

**GitHub 链接一定要放**，而且要有连续提交记录。2027 年面试官真的会点开看。

## 八、面试必须准备好的六个追问

对应主力项目的六个技术点，每个都要能答三层：

| 技术点 | 第一层 | 第二层 | 第三层 |
| --- | --- | --- | --- |
| 双端鉴权 | 员工和用户为什么两套体系 | token 过期怎么续 | 怎么让 token 立刻失效（Redis 黑名单） |
| Redis 缓存 | 缓存了什么 | 为什么缓存这个不缓存那个 | 穿透/击穿/雪崩/一致性怎么处理 |
| 索引 | 哪几个字段建了索引 | 为什么是这几个 | explain 的 type 到哪一级 |
| RAG 问答 | 切片多大，为什么 | 召回不准怎么办 | 怎么防止模型胡说 |
| 分布式锁 | 为什么用 Redis 锁不用数据库锁 | 锁超时了怎么办 | 怎么防止误删别人的锁 |
| 支付回调 | 回调重复到达怎么办（幂等） | 怎么保证订单状态一致 | 支付成功但回调没到怎么办 |

**这份表就是面试稿。** 每写完一个模块，回来填一行。

### JVM 补课（唯一缺口）

JD 写的是「了解 JVM 基础」，不是「JVM 调优」，两者差 20 倍工作量：

| 层级 | 要学什么 | 时间 |
| --- | --- | --- |
| **了解 JVM 基础**（要补） | 堆/栈/方法区、GC 算法（复制、标记整理、标记清除）、类加载过程、OOM 怎么排查 | **10–15 小时** |
| JVM 调优（不碰） | G1/ZGC 参数调优、内存模型源码、性能火焰图 | 200 小时+，校招不问 |

**安排：2 月初和 Redis 一起学。**

### JD 动词分级（以后看 JD 先看动词）

| 动词 | 真实含义 | 时间成本 |
| --- | --- | --- |
| **了解** | 能说清是什么、解决什么问题 | 2 小时读一篇文章 |
| **熟悉** | 用过，能独立写出来 | 20–30 小时 |
| **熟练掌握** | 能讲原理、踩过坑、答得出三层追问 | 100 小时+ |

真正需要投入「熟练掌握」的只有四件事：**Java 基础、SpringBoot、MySQL、Redis** —— 正好是现有路线的主干。其余「了解」级别的词，不值得为它改路线。

### 一个必须提前知道的现实

按 465h 的账算，**12 月和 1 月的量大概率学不完**：12 月要覆盖 0373–0552 共 180 集 / 105h，等于 35 分钟一集，而视频本身就有 20–30 分钟。

所以 2 月底的真实状态更可能是：**集合刚学完，多线程和 IO 没动**。

这不用慌，3 月的处理方式：

- **多线程**必须补（八股必问，20 集，20h）
- **IO 流**可以放弃（校招初级岗基本不问，用到再查）

也就是说 3 月要预留出 20h 给多线程，别把 3 月排满 Spring AI。
