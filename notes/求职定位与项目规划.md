## 五、岗位方向

**主投：Java 后端开发工程师（业务研发方向）**

- 搜索关键词只用三个：`Java 后端`、`Java 开发`、`后端开发`
- 投递顺序：杭州中厂 → 杭州中小 SaaS → 杭州外包/驻场 → 南昌正规企业
- 不投：安卓、前端、测试、实施、大数据、算法（技能栈不重叠，转型不可逆）

**岗位归属与职责**（详见对话记录）：研发中心下的业务研发部，核心产出是「能稳定跑的接口」。实习生实际做边缘需求、修 bug、补文档，不会一上来碰核心链路。

## 六、项目设计

### 主力项目：校园/团队知识库 + AI 文档问答

| 模块 | 功能 | 技术点 |
| --- | --- | --- |
| 用户 | 注册登录、JWT 鉴权、三角色 | 拦截器、无状态鉴权、Redis 黑名单 |
| 文档 | 上传 PDF/Word、标签分类、分页、下载 | 文件 IO、MyBatis-Plus 分页、异步解析 |
| 检索 | 关键词搜索、热点文档缓存 | MySQL 索引、Redis 缓存穿透防护 |
| AI 问答（3–4 月加） | 文档切片 → 向量化 → 检索增强 → 答问 | Spring AI + 向量库 |

**为什么匹配 8–12k 档：**
- 技术栈完整命中 JD 原文（SpringBoot + MyBatis-Plus + MySQL + Redis）
- 每个模块都有能被追问三层的问题（见下）
- AI 部分是明确的加分项：招银网络 JD 原文写「了解大模型，具备相关实践经验者优先」

**为什么不做外卖/商城：** AI 插不进去；业务模型复杂到讲不清设计动机；面试官一眼看穿照抄教程。

### 加餐项目：短链服务（可选，约 2 周）

主力项目偏业务，证明不了技术深度。短链代码量 800 行以内，但能讲透四件事：

1. 发号器：Redis 自增 vs 雪花算法，各自的问题
2. Base62 编码：为什么不用 MD5 截断
3. 缓存：热点 key 怎么设计，缓存穿透怎么防（布隆过滤器）
4. 跳转：301 还是 302，为什么

**它的作用不是替代主项目，是在面试里证明「我不只是会 CRUD」。**

### 明确不做

- 照抄苍穹外卖/瑞吉外卖（2027 年面试官一眼看穿，答不出「你为什么这样设计」）
- 微服务（时间不够，碰了等于什么都没做）
- 秒杀（需要压测、限流、分布式锁，讲不明白）

## 七、简历项目部分的写法

### 结构：动作 + 技术 + 结果，一行一件事

```
校园知识库共享平台 | Java 后端 | 个人项目 | 2027.01–2027.03
技术栈：SpringBoot 3 + MyBatis-Plus + MySQL 8 + Redis + Spring AI
· 基于 JWT + 拦截器实现无状态鉴权，三角色权限隔离，token 失效用 Redis 黑名单处理
· 文档上传异步解析入库，接口平均响应从 2.1s 降至 180ms
· Redis 缓存热点文档详情，实测命中率 87%，未命中时用空值缓存防穿透
· 基于 Spring AI + 向量库实现文档问答，切片 512 token，Top-3 召回
```

### 五条硬规则

1. **不写功能清单**。「实现了用户的增删改查」等于没写，谁都会。
2. **数字必须自己测过**。面试官一定问「怎么测的」，编的撑不过两个追问。
3. **写上去的每个技术点都要能被追问三层**。写了 Redis 就要能答缓存穿透、雪崩、一致性。
4. **技术栈不堆砌**。写了 SpringCloud 就要能讲注册中心原理，讲不出就是减分。
5. **项目名别叫「XX管理系统」**。叫「知识库共享平台」「短链服务」这种，一眼看出是做什么的。

### 简历整体排序（重要）

```
1. 项目经历      ← 二本学历下，这是唯一能翻盘的部分
2. 专业技能      ← 分「熟练/熟悉/了解」三档，别全写熟练
3. 教育背景      ← 二本放后面，不占首屏
4. 其他          ← 蓝桥杯、GitHub 链接（绿墙）、博客
```

**GitHub 链接一定要放**，而且要有连续提交记录。2027 年面试官真的会点开看。

## 八、面试必须准备好的六个追问

对应主力项目的六个技术点，每个都要能答三层：

| 技术点 | 第一层 | 第二层 | 第三层 |
| --- | --- | --- | --- |
| JWT 登录 | 为什么不用 Session | token 过期怎么办 | 退出登录怎么让 token 立刻失效 |
| 文件上传 | 大文件怎么处理 | 上传失败怎么重试 | 存本地还是对象存储，为什么 |
| 分页 | limit offset 怎么用 | 深分页为什么慢 | 怎么优化（游标/延迟关联） |
| Redis 缓存 | 缓存了什么 | 为什么缓存这个不缓存那个 | 穿透/雪崩/一致性怎么处理 |
| 索引 | 哪几个字段建了索引 | 为什么是这几个 | explain 的 type 到哪一级 |
| AI 问答 | 切片多大，为什么 | 召回不准怎么办 | 怎么防止模型胡说 |

**这份表就是面试稿。** 每写完一个模块，回来填一行。

### JVM 补课（唯一缺口）

JD 写的是「了解 JVM 基础」，不是「JVM 调优」，两者差 20 倍工作量：

| 层级 | 要学什么 | 时间 |
| --- | --- | --- |
| **了解 JVM 基础**（要补） | 堆/栈/方法区、GC 算法（复制、标记整理、标记清除）、类加载过程、OOM 怎么排查 | **10–15 小时** |
| JVM 调优（不碰） | G1/ZGC 参数调优、内存模型源码、性能火焰图 | 200 小时+，校招不问 |

**安排：2 月初和 Redis 一起学。**

### JD 动词分级（以后看 JD 先看动词）

| 动词 | 真实含义 | 时间成本 |
| --- | --- | --- |
| **了解** | 能说清是什么、解决什么问题 | 2 小时读一篇文章 |
| **熟悉** | 用过，能独立写出来 | 20–30 小时 |
| **熟练掌握** | 能讲原理、踩过坑、答得出三层追问 | 100 小时+ |

真正需要投入「熟练掌握」的只有四件事：**Java 基础、SpringBoot、MySQL、Redis** —— 正好是现有路线的主干。其余「了解」级别的词，不值得为它改路线。
